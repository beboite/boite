# Browser automation on public sites

Measured on 2026-09-24 against the Jev plugin at `fea0d0e`.
The production browser loop was not changed for these measurements.

The [subsequent adapter fixes and rerun](2026-09-24-browser-fixed.md) completed
9/9 workflows. This report preserves the original failing baseline.

## Results

The shipped plugin completed 0 of 9 full workflows. Each GPT arm completed
3 of 3. The GPT samples are one attempt per site, so these counts are a
diagnostic result, not an estimate of production reliability.

Times below exclude initial navigation and browser startup, and include
model thinking and tool calls. Failed Jev runs are not speed wins.

| Task | Jev, three attempts | GPT visual, one attempt | GPT + agent-browser, one attempt |
| --- | --- | --- | --- |
| Wikipedia | 0/3, initial page rejected | Pass, 22.86 s | Pass, 17.42 s |
| GitHub | 0/3, initial page rejected | Pass, 84.99 s | Pass, 31.06 s |
| GOV.UK | 0/3 full workflow; 2/3 correct destination | Pass, 33.52 s | Pass, 27.27 s |

Startup plus initial navigation took 1.13 to 2.37 seconds across the GPT
runs. All six GPT successes also meet a 120-second budget including startup.
Every completed trial recorded zero owned browser processes after cleanup.
Individual durations, calls, action counts and outcomes are in the
[result JSON](2026-09-24-browser.json).

## Protocol

The tasks in [browser-real.ts](../browser-real.ts) use live public sites:

| Site | Required result |
| --- | --- |
| Wikipedia | Search for Ada Lovelace and open her article about the Analytical Engine. |
| GitHub | Navigate from the agent-browser repository to release v0.37.1 and display its Windows executable asset. |
| GOV.UK | Search for `renew adult passport`, open the adult passport guide, then its Renew section. |

All runs use an isolated, logged-out Edge 153.0.4234.48 profile, muted and
headless, with a 1280 by 800 viewport. No downloads, purchases or applications
are submitted. The native driver is the unmodified agent-browser 0.37.1 binary.

The three arms are:

- Shipped Jev: the real `browser.start` RPC, production loop and Jev 1.13.0 API.
- GPT visual: a separate GPT-6 Astra subscription agent sees screenshots and
  uses coordinate mouse, keyboard and scrolling commands.
- GPT with agent-browser: another GPT-6 Astra subscription agent sees
  accessibility snapshots and uses references, fields, clicks and keys.

The GPT arms use [browser-session.ts](../browser-session.ts). Both send native
agent-browser commands through its JSONL daemon protocol; neither includes
the CLI argument parser. The visual arm cannot request DOM or accessibility
data. This is a screenshot-based GPT computer-use comparison, not a run of
OpenAI's integrated Computer Use tool or its Responses API computer tool.

Initial navigation is the only supplied URL operation. Workers receive the
same goals and values, without walkthroughs or selectors. GPT execution time
includes model thinking, shell calls and screenshot loading. Browser startup
and initial navigation are recorded separately. Jev permits 30 loop decisions
and 120 seconds including startup. GPT permits 30 input actions and 120 seconds
after startup. These limits differ and are recorded rather than equated.
No published success depends on the extra startup allowance. None of the
attempts reaches its action or decision limit.

The grader reads the final URL and rendered body text independently. For
GOV.UK it also requires an observed search URL containing the supplied query.
A model's completion claim alone cannot pass. Traces, final screenshots and
owned-process cleanup counts are written to the selected output directory.
The published results apply the same exact GOV.UK query predicate to all
recorded URLs, including the GPT traces.

Excluded runs are listed in the result JSON. They include protocol smoke
tests, exploratory runs with a different browser, an initially incorrect
GitHub asset suffix, and one visual Wikipedia attempt interrupted by a
service restart before its first action. That attempt was restarted with a
fresh profile and clock. The workers ran sequentially after setup.

## Findings in the shipped integration

Wikipedia's initial snapshot contains 34,931 characters. GitHub's contains
194,736 to 197,299. Both exceed the plugin's 24,000-character limit, so all
six attempts stop before making a Jev request. These are integration failures;
they do not measure Jev's ability to choose actions on those pages.

On GOV.UK, the search field has ARIA role `combobox` but is an editable input.
The plugin maps every combobox to `select`. The native command reports success
without filling this field, and the resulting URL is `/search/all?keywords=`.
Two of three attempts later reach the requested guide through category links.
The plugin reports success, but the independent workflow grader rejects them.
The third attempt hands control back at the empty search page.

Across the nine controlled Jev runs, 15 model requests consumed 75,912 input
tokens. Request latency was 226.4 to 781.4 ms, with a 244.8 ms median.
The estimated model charge is $0.003188 at TypeSafe's published
[$0.042 per million input tokens](https://docs.typesafe.ai/models).
This is a list-price estimate, not an invoice. GPT runs use the subscription;
no per-task dollar cost or isolated token count was measured.

The observed failures require changes to page selection, editable-combobox
handling and completion checks before this plugin can reliably perform these
workflows. Model response speed does not resolve those failures.

## Reproduce

For Jev, set `BOITE_BENCH_BROWSER=1`, `TYPESAFE_API_KEY`,
`BOITE_BROWSER_TEST_BINARY` to the pinned native binary, and
`BOITE_BENCH_OUTPUT` to an empty output directory. Run:

```sh
bun run bench/browser-real.ts
```

It runs three repetitions per task by default and rotates task order.
`BOITE_BENCH_REPETITIONS` accepts 1 through 10. Each run writes a JSON trace
and screenshot; `summary.json` contains the measured outcomes.

For a subscription-driven GPT run, set `BOITE_BROWSER_TEST_BINARY` and
`BOITE_BENCH_SESSION_OUTPUT`, then start:

```sh
bun run bench/browser-session.ts
```

Set `BOITE_BENCH_CONTROL` to the printed control-file path in the worker's
environment. The helper reads its ephemeral token without printing it:

```sh
bun run bench/browser-session-client.ts start '{"arm":"visual","task":"wikipedia","run":1}'
bun run bench/browser-session-client.ts command '{"commands":[{"action":"screenshot"}]}'
bun run bench/browser-session-client.ts finish '{}'
bun run bench/browser-session-client.ts shutdown '{}'
```

Use `classic` for the snapshot arm. Each worker must observe the returned
page, choose its own actions and call `finish` promptly. `start`, `command`
and `finish` are measured, not a scripted replay. The service permits one
active task, and `shutdown` closes its owned core and browser processes.

Type-check the browser benchmark entry points with:

```sh
bun run --cwd packages/core tsc -p ../../bench/browser.tsconfig.json
```
