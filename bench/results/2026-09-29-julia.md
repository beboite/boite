# Julia-1 browser experiments

Julia-1 did not make the tested browser controller dependable. This experiment replaces the choice of the next action after Luna has already generated the alternatives. It does not replace the planner or remove its subscription usage. The live comparison uses eight real workflows, independently reviewed evidence and a 180-second execution budget.

## What was tested

[Julia-1](https://huggingface.co/SupersonicLabs/Julia-1) is a text model for selecting one of supplied alternatives. Its official interface accepts 2 to 20 choices. It does not generate browser commands or plan a conversation. The pinned checkpoint and ONNX export, exact runtime hashes, hardware and encoder settings are in [runtime.json](2026-09-29-julia/runtime.json).

The browser runs on Windows through agent-browser 0.38.1 with fresh, logged-out Edge profiles. Inference runs on a Linux Ryzen 7 5825U using two CPU threads and FP32. This is not an Apple Silicon test. The comparison planner is Luna max with acknowledged Fast/priority settings through the ChatGPT subscription, with no API key.

Both arms receive the same goal and observation policy. Luna proposes grounded actions and its preference. The control executes that preference; the Julia arm executes Julia's selection from shuffled descriptions. Julia receives neither the preference nor command objects. Luna receives screenshots; Julia receives a scoped text observation. Candidate-generation time counts in both arms. The [protocol](2026-09-29-julia-protocol.md) explains limits, omissions, provenance and reproduction commands.

## Live workflows

The primary comparison scores 16 attempts on eight tasks. Eighteen were collected: both original Maps attempts remain in the [original export](2026-09-29-julia/live-timing-original.json), and their [paired replacements](2026-09-29-julia/maps-replacement.json) use identical archived source hashes. Julia's original Maps browser failed before any decision. Both originals are explicitly excluded from the matched score; ordinary failures after decisions remain included.

| Workflow | Luna criteria | Luna finished successfully | Julia criteria | Julia finished successfully |
| --- | ---: | --- | ---: | --- |
| GitHub issue filters and author tab | 3/3 | Yes | 3/3 | No |
| GitHub latest release and ZIP | 2/3 | No | 1/3 | No |
| Google Maps walking route, replacement pair | 3/3 | Yes | 3/3 | No |
| Amazon two products, variants and sellers | 3/3 | Yes | 1/3 | No |
| Booking dates and hotel filters | 0/3 | No | 0/3 | No |
| YouTube filters and video description | 2/3 | No | 1/3 | No |
| Wikipedia language, revision history and NASA | 3/3 | Yes | 3/3 | No |
| Google Flights round trip, two adults, nonstop | 3/3 | No | 1/3 | No |
| Total | 19/24 | 4/8 | 13/24 | 0/8 |

Julia made 104 successful inference calls and disagreed with the planner preference 55 times. Disagreement is not an accuracy label. GitHub, Maps and Wikipedia reached all three evidence criteria but timed out without executing finish or delivering an answer. On the Maps replacement's final decision, finish was available and preferred by Luna; Julia selected another observation. This demonstrates a termination problem in this controller, rather than proving that Julia cannot read the facts.

Across all eight primary attempts per arm, including failures, median startup-plus-execution time was 147.8 seconds for Luna and 185.5 seconds for Julia. The Julia server median was 3,059 ms and p95 was 7,957 ms over 104 calls; the caller median was 3,108 ms. Median selector input was 1,700.5 tokens. Candidate generation itself had medians of 7,181 ms in the control and 6,419 ms in the Julia arm. These live figures explain why a tiny-choice latency cannot predict full browser speed.

The [complete comparison export](2026-09-29-julia/live-comparison.json) preserves criteria, all attempts, explicit exclusions, input omissions, decision mappings and evidence hashes. Planner cumulative usage was 9,198,697 tokens for Luna and 6,252,258 for the Julia arm, including respectively 7,994,624 and 5,309,184 cached input tokens. Uncached input was 1,141,078 and 888,661 tokens; Julia's separate selector encoded 179,068 tokens. These are saved app-server usage counters, not monetary costs or eliminated planning work. Each final cumulative counter was counted once and checked against saved incremental updates. Native token-count events were not preserved.

The release control downloaded an actual 42,612,768-byte ZIP, but its claimed date was not corroborated by the visible release date. The Flights control reached a corroborated 341 EUR round-trip selection but did not finish before the deadline. YouTube reached a qualifying long video and expanded description without reporting the requested phrase in time. These remain failures despite useful partial progress.

Both Booking searches lost their requested dates and returned generic Paris pages. The evidence does not establish the cause. Julia's Amazon run failed on native new-tab/capture timeouts after eight completed inference calls; that ordinary runtime failure stays in its score. No live case demonstrated the separately identified snapshot-URL registry mismatch.

The [engineering preflights](2026-09-29-julia/engineering-preflights.json) preserve another 12 starts with earlier parser, observation or recorder protocols. They are not pooled into the primary score. Separate videos use repaired URL handling and recorder transitions, with their own source hashes; they do not replace primary failures.

## Saved observations

The replay dataset contains 52 retrospectively selected decisions from the September 24 browser evidence. Forty are local actions, eleven are fact checks and one is a completion check. These are correlated examples with expert-written questions, not an independent sample of arbitrary websites.

Four initial configurations produced 208 requests. Each accepted 40 inputs and rejected the same 12 descriptions for exceeding the model's 48-token option contract. On accepted inputs, each configuration selected a semantically acceptable choice in 13/40 cases. The [label audit](2026-09-29-julia/label-audit.json) preserves ambiguous choices and three cases where the first state projection lost numeric evidence. Historical labels and semantic acceptance remain separate.

Shorter, natural descriptions were then tested on the same cases. This post-hoc representation change produced another 144 requests, all accepted:

| Input | Accepted | Historical label matched | Semantically acceptable | Median inference | p95 inference |
| --- | ---: | ---: | ---: | ---: | ---: |
| Supplied full state | 52/52 | 23/52 | 25/52 | 3,326 ms | 24,469 ms |
| Target state | 52/52 | 27/52 | 30/52 | 1,085 ms | 18,840 ms |
| Local action router | 40/40 | 20/40 | 23/40 | 307 ms | 731 ms |

The local router supplies the title, URL, goal, expert question and short alternatives. It explicitly omits the DOM and body. Its 307 ms median therefore accompanies 57.5% acceptable choices on a prepared action subset; it is not browser completion latency. Fact and completion inputs retain their full supplied state in the other configurations. Replay medians use the upper middle value for even counts, as defined in the protocol.

Torch and ONNX agreed on all 40 accepted initial scoped predictions, with maximum logit difference 0.000116. Rotating those alternatives changed 18 of the 40 semantic selections despite leaving the aggregate score unchanged. These checks found no index-mapping or serialization explanation for the low score.

The [initial results](2026-09-29-julia/initial-replay-results.json), [natural-language results](2026-09-29-julia/natural-language-replay-results.json), [router results](2026-09-29-julia/natural-local-router-replay-results.json) and [summary](2026-09-29-julia/natural-replay-summary.json) preserve all 352 attempts. Gold labels never enter requests. Two [tiny control choices](2026-09-29-julia/control-probes.json) passed at 47 and 59 ms of inference; authentication and option-overflow checks also passed. Those controls establish a working runtime, not web reliability.

## Scope of the result

This round does not support making Julia the default browser selector. Reducing input size improves CPU latency but loses information, and acceptable local choices do not establish planning or termination. The tested Julia arm still pays Luna's planning cost.

The [September 24 controller comparison](2026-09-24-browser-lab.md) remains historical evidence for other controllers. Its native, Playwright and GPT visual trials are not fresh matched baselines for this Julia experiment. This round does not rank Julia against every computer-use stack.

No authenticated workflows, uploads, account mutations, CAPTCHA completion, native desktop applications, quantization, GPU inference or Apple hardware were tested. Linux inference does not verify Linux browser execution. One attempt per task cannot establish a production success rate, and these experiments do not expand the installed Jev plugin's supported operations.
